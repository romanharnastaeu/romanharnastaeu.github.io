Private-source project · Full-stack case study

VeriGoods

A TypeScript-first, mobile-first product lookup and decision-support platform that connects barcode and name search with profile-aware food evaluation, objective beauty ingredient-risk screening, history, favorites, and Better Options discovery.

Role
Full-stack product engineering
Application
Expo React Native + Expo Router
Backend
Supabase Edge Functions
Data
PostgreSQL + row-level security

01 · Context

Useful answers require more than a product lookup.

Public product records vary in quality. Barcodes can be invalid, food and beauty products require different reasoning, source records can be incomplete, and the same food may be evaluated differently for two profiles.

VeriGoods treats those constraints as part of the product model. It validates inputs, identifies the product type, preserves source and confidence information, applies the correct domain workflow, and returns explicit not-found, ambiguous, or insufficient-data states when the evidence is not strong enough.

02 · Architecture

A controlled path from query to decision support.

  1. 01Expo applicationAuth, search, scan, profiles, and product views
  2. 02Edge FunctionsValidation, lookup orchestration, and normalized responses
  3. 03Product providersOpen Food Facts, Open Beauty Facts, USDA, and UPCitemdb
  4. 04PostgreSQL + RLSProfiles, products, history, favorites, and evaluation data
  5. 05Decision workflowsFood evaluation, beauty screening, and Better Options

The application checks local product and cache data where appropriate before external enrichment. Server-side functions keep private credentials out of the client and return structured statuses so the interface can distinguish usable results from missing, ambiguous, or incomplete data.

03 · Delivered capabilities

A working product foundation across client, API, and data layers.

  • Search and scanning

    Name search, manual barcode entry, native camera scanning, GTIN validation, provider fallbacks, product details, and authenticated lookup history.

  • Profiles and persistence

    Supabase Auth, account synchronization, active profiles, goals, allergens, avoid ingredients, weighted preferences, favorites, and server-backed history controls.

  • Separate evaluation domains

    Profile-aware food evaluation and objective beauty/self-care ingredient-risk screening use distinct rules, statuses, and sufficient-data requirements.

  • Better Options and administration

    Live type-isolated alternatives, conservative health and ingredient gates, batch hydration, retrieval diagnostics, and a separate admin data foundation.

04 · Engineering decisions

Conservative behaviour at uncertain boundaries.

01

Validate identifiers before provider calls

GTIN-8, UPC-A, EAN-13, and GTIN-14 check digits are verified first, and only valid UPC/EAN/GTIN equivalence variants are attempted.

02

Keep food and beauty logic separate

Food uses profile, allergen, nutrition, and confidence rules. Beauty uses a table-driven ingredient-risk workflow and never borrows food scoring logic.

03

Make uncertainty visible

Weak classification pauses evaluation for user confirmation, while missing or truncated evidence produces an insufficient-data result instead of a confident verdict.

04

Protect application data

Row-level security scopes user-owned records, privileged account fields are protected server-side, and admin account changes pass through a controlled Edge Function.

05

Recommend within hard boundaries

Better Options never mix product types and exclude profile conflicts, objective regressions, high-risk beauty results, and insufficient-data candidates from the primary list.

05 · Scope

Decision support, not medical advice.

The current application is a working technical foundation with prototype-style UI and an MVP rules engine. Its food and beauty results depend on available public product data and intentionally avoid medical, dietary, dermatology, toxicology, or regulatory-compliance claims.

Current boundary: evaluation labels describe detected profile conflicts, public health signals, or ingredient-rule matches. They do not prove that a product is safe or unsafe for a specific person.
